# OctoAcme Personas

This document defines typical roles and responsibilities used in OctoAcme project docs and exercises.

---

## Core Roles

### Developers

#### Role Summary
Developers design, build, test, and deliver software components. They collaborate with product and project leads to implement features that meet acceptance criteria and quality standards.

#### Responsibilities
- Implement features and fixes to meet acceptance criteria
- Write and maintain tests and documentation
- Participate in design and code reviews
- Assist in estimating and planning work
- Help identify technical risks and propose mitigations

#### Goals
- Deliver reliable, maintainable code
- Reduce cycle time from idea to production
- Maintain high test coverage and observability

#### Typical Communication
- Daily standups and sprint planning
- PR descriptions and code review comments
- Technical design docs when needed

#### Key Interactions
- Collaborates with UX Designer on feature usability and acceptance criteria
- Works with QA/Testing team on test coverage and quality gates
- Coordinates with Release Manager on deployment readiness

---

### Product Managers

#### Role Summary
Product Managers define what should be built to deliver customer and business value. They own the product vision, prioritize the backlog, and measure outcomes.

#### Responsibilities
- Define problem statements and success metrics
- Prioritize the roadmap and backlog
- Collaborate with stakeholders and engineering on trade-offs
- Validate solutions through user research and metrics

#### Goals
- Maximize customer value and impact
- Make clear, data-driven prioritization decisions
- Ensure product-market fit and usability

#### Typical Communication
- Weekly alignment with PM and engineering leads
- Roadmap updates and stakeholder briefings
- Acceptance criteria and feature specs

#### Key Interactions
- Partners with UX Designer for user research and feedback
- Consults with Technical Writer to ensure feature documentation is planned
- Engages with Support Lead to incorporate customer feedback and pain points

---

### Project Managers

#### Role Summary
Project Managers coordinate delivery activities, manage schedules, risks, and communications. They enable the team to deliver on commitments efficiently.

#### Responsibilities
- Create and maintain project plans and timelines
- Manage risks, dependencies, and resource constraints
- Facilitate meetings (kickoff, planning, retrospectives)
- Ensure consistent project documentation and status reporting
- Coordinate cross-team and stakeholder communication

#### Goals
- Deliver projects on time and within scope
- Minimize unplanned work and escalations
- Maintain transparency and alignment across stakeholders

#### Typical Communication
- Weekly status updates and stakeholder reports
- Risk registers and decision logs
- Coordination via project boards and meeting facilitation

#### Key Interactions
- Works closely with Scrum Master/Agile Coach on process adherence and impediment removal
- Coordinates with Release Manager on release timelines and deployment windows
- Partners with Support Lead to plan for post-launch support and feedback integration

---

## Supporting Roles

### UX Designer

#### Role Summary
UX Designers conduct user research, create wireframes and prototypes, and validate that features meet usability standards. They bridge the gap between customer needs and technical implementation.

#### Responsibilities
- Conduct user research and usability testing
- Create wireframes, mockups, and design specifications
- Define and validate usability acceptance criteria with Product Managers
- Participate in design reviews and provide feedback on implementation
- Document design decisions and design systems for consistency
- Collaborate with Developers to ensure design fidelity in implementation

#### Goals
- Deliver intuitive, user-centered experiences
- Reduce usability defects and improve customer satisfaction
- Establish and maintain design consistency across the product

#### Typical Communication
- Weekly design sync with Product Manager and engineering leads
- Design review meetings with stakeholders
- Usability test reports and design documentation
- Collaborative design sessions with Developers

#### Key Interactions
- Partners with Product Manager to understand customer problems and success metrics
- Works with Developers to validate design implementation and provide guidance
- Contributes usability requirements to acceptance criteria
- Supports Technical Writer with UI/UX documentation and screenshots

---

### Technical Writer

#### Role Summary
Technical Writers create, maintain, and ensure clarity of all project documentation, including feature documentation, user guides, API docs, and process runbooks. They ensure consistent, accurate communication across the organization.

#### Responsibilities
- Plan documentation strategy alongside Product Manager and Developers
- Create and maintain user-facing documentation and guides
- Document APIs, configuration, and technical architecture
- Maintain process documentation and runbooks (e.g., incident response, deployment)
- Ensure documentation is kept up-to-date as features evolve
- Coordinate with all roles to capture requirements and validate content accuracy

#### Goals
- Reduce support burden by providing clear, accessible documentation
- Improve onboarding time for new team members
- Maintain a single source of truth for product and process knowledge

#### Typical Communication
- Documentation planning meetings during project kickoff and planning phases
- Reviews with Product Manager, Developers, and UX Designer on content accuracy
- Documentation release notes alongside feature releases
- Coordination with Support Lead on FAQ updates and known issues

#### Key Interactions
- Collaborates with Product Manager on feature scope and success criteria documentation
- Reviews code and design docs with Developers to ensure technical accuracy
- Partners with UX Designer on UI documentation and user guide screenshots
- Works with Release Manager on release notes and deployment runbooks
- Supports Support Lead with FAQ and troubleshooting documentation

---

### Scrum Master / Agile Coach

#### Role Summary
Scrum Masters (or Agile Coaches in non-Scrum environments) facilitate agile ceremonies, remove team impediments, and help the team continuously improve their delivery process. They serve as guardians of the agile methodology and team health.

#### Responsibilities
- Facilitate daily standups, sprint planning, reviews, and retrospectives
- Identify and help remove team blockers and impediments
- Coach the team on agile principles and practices
- Monitor team velocity and health metrics
- Escalate systemic issues to Product Manager or Project Manager
- Foster a culture of psychological safety and continuous improvement

#### Goals
- Maximize team productivity and flow
- Improve team delivery predictability
- Foster a healthy, high-performing team culture

#### Typical Communication
- Daily standups and sprint ceremonies
- Weekly sync with Project Manager on team health and blockers
- Retrospective notes and action item tracking
- Escalation communications to leadership when needed

#### Key Interactions
- Works closely with Project Manager on timeline management and risk escalation
- Partners with the delivery team (Developers, QA) on process improvements
- Coordinates with Release Manager on deployment readiness gates
- Escalates dependencies or blockers that impact multiple teams

---

### Release Manager

#### Role Summary
Release Managers oversee the end-to-end release process, coordinate deployments, ensure quality gates are met, and maintain the integrity of production systems. They act as the coordinator between development, QA, operations, and support teams.

#### Responsibilities
- Create and maintain release plans and deployment schedules
- Ensure all pre-release requirements are met (testing, security scans, documentation)
- Coordinate deployment activities across teams and environments
- Manage rollback procedures and incident response during deployments
- Maintain release checklists and deployment runbooks
- Document and communicate release information to stakeholders and support teams
- Coordinate with Support Lead to ensure readiness for customer impact

#### Goals
- Minimize deployment risk and ensure system reliability
- Reduce time to deployment and improve release velocity
- Maintain clear communication and transparency during releases
- Enable quick incident response and rollback when needed

#### Typical Communication
- Release planning meetings during project planning phase
- Pre-release status meetings and deployment coordination calls
- Release notes and stakeholder communications
- Post-deployment verification and incident escalation if needed

#### Key Interactions
- Coordinates with Developers and QA on code readiness and testing completion
- Works with Project Manager on release timeline and milestone tracking
- Partners with Technical Writer on release notes and deployment documentation
- Engages with Support Lead to brief them on changes and expected customer impact
- Communicates with Operations/DevOps teams on deployment execution

---

### Support Lead

#### Role Summary
Support Leads act as the primary point of contact for post-launch support, customer issue escalation, and feedback integration. They bridge the gap between customer needs and product direction by channeling real-world insights back into the roadmap.

#### Responsibilities
- Triage and escalate critical production issues
- Capture customer feedback and pain points
- Identify trends in customer issues and feature requests
- Partner with Product Manager to prioritize fixes and improvements based on customer impact
- Communicate known issues and workarounds to support teams
- Provide input on documentation clarity and gaps based on customer questions
- Participate in incident response and post-mortems

#### Goals
- Minimize customer impact from issues and bugs
- Improve customer satisfaction and retention
- Ensure customer voice informs product decisions
- Reduce support volume through proactive documentation and issue prevention

#### Typical Communication
- Weekly briefings from Release Manager on new features and changes
- Regular feedback reviews with Product Manager
- Issue escalation and incident communication with technical teams
- Support team coordination and documentation updates

#### Key Interactions
- Receives release briefs from Release Manager and communicates changes to support teams
- Provides customer feedback and issue trends to Product Manager for prioritization
- Works with Technical Writer to identify documentation gaps and FAQ updates
- Escalates critical issues to Project Manager and Scrum Master for team triage
- Partners with Developers on urgent bug fixes and hotfixes

## Cross-Functional Collaboration Matrix

| Role | Works With | Primary Interaction |
|------|-----------|-------------------|
| Developer | Product Manager, UX Designer, QA, Scrum Master, Release Manager | Daily standups, code reviews, design collaboration |
| Product Manager | Developers, UX Designer, Support Lead, Project Manager, Stakeholders | Weekly syncs, backlog refinement, roadmap planning |
| Project Manager | Scrum Master, Release Manager, Product Manager, Stakeholders | Weekly status, risk management, escalation |
| UX Designer | Product Manager, Developers, Technical Writer | Design reviews, usability testing, implementation collaboration |
| Technical Writer | All roles (coordinates documentation across teams) | Planning, review cycles, release coordination |
| Scrum Master | Developers, Product Manager, Project Manager, Stakeholders | Ceremonies, impediment removal, team coaching |
| Release Manager | Developers, QA, Technical Writer, Support Lead, Operations | Pre-release coordination, deployment, post-launch verification |
| Support Lead | Product Manager, Release Manager, Technical Writer, Developers (for escalations) | Feedback integration, issue escalation, documentation improvement |

## How these personas are used in the exercise
- Use these persona definitions to frame scenarios and sample interactions in the Skills Exercise.
- Each persona can be used as a persona prompt for Copilot Spaces to shape role-specific guidance.
- The cross-functional collaboration matrix helps clarify responsibilities and reduce gaps in accountability.
- Supporting roles address common execution challenges in scaling projects: design quality, documentation clarity, process adherence, deployment safety, and customer feedback integration.
